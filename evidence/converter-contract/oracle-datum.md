# Oracle Datum converter contract

The owned Oracle converter family is implemented under the supplier-compatible `com.sunwayworld.framework.converter.date` namespace, with lifecycle and JDBC helpers under `com.sunwayworld.owned.internal.*`. Pinned public dependencies include Oracle JDBC 19.3.0.0 and Spring JDBC/transaction modules; no supplier framework class is loaded by the owned artifact.

The closed declaration gate passes for 144 selected supplier classes after adding the four Oracle converter declarations and runtime bridge. `test-oracle-datum-contract.sh` passes synthetic `oracle.sql.DATE` and `TIMESTAMP` conversion, source type metadata, and date formatting. TIMESTAMPTZ/TIMESTAMPLTZ paths use a real Spring `DataSource` from the owned application context and transaction-aware `DataSourceUtils`; when a connection is not transaction-bound it is released after the conversion.

The supplier's TIMESTAMPTZ/TIMESTAMPLTZ paths obtain a connection through its private `MybatisHelper`; this owned implementation preserves the public converter seam while using the project-owned context bridge. No production Oracle was contacted. A real Oracle `DataSource` integration test remains required before claiming runtime equivalence for timezone-bearing Datum values.

`test-owned-context-lifecycle.sh` also verifies replacement and identity-checked clearing: closing or clearing an older context cannot erase a newer registered context. The bootstrap run contract passes with both `SunwayApplication.run` overloads. A synthetic DATE/TIMESTAMP smoke covers driver conversion without fabricating a timezone result; TIMESTAMPTZ/TIMESTAMPLTZ remains bounded to the real DataSource path above.

The parentless supplier/owned differential fixture passes 198 observations in each of UTC, Asia/Shanghai, and America/New_York. It covers null, DATE, TIMESTAMP, malformed bytes, generic Datum, unchecked and checked failures, target/source metadata, canConvert, fresh converter identity, and Oracle Datum-to-string leaves. The fixture intentionally excludes TIMESTAMPTZ/TIMESTAMPLTZ because the supplier obtains a private application connection; those paths are covered only by the owned bridge lifecycle and remain bounded by the real Oracle DataSource requirement.
