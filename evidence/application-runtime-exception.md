# ApplicationRuntimeException and custom-number boundary

`ApplicationRuntimeException` now has the supplier-facing class and all three constructors under `com.sunwayworld.framework.exception.core`, while message lookup remains in the project-owned internal `OwnedMessageSource` adapter. The adapter accepts a real Spring `MessageSource`, uses the current `LocaleContextHolder` locale, retries `Locale.CHINA` when a result is blank or equals the key, and returns literal keys when no owned source is installed. It does not add a public `I18nHelper` facade.

`test-application-runtime-exception.sh` compares 841 constructor/message observations against the pinned supplier class using Spring `StaticMessageSource`: translated and China fallback text, missing and equal-key results, Unicode whitespace, null/empty arguments, all cause forms, cause identity, and four locales all pass. The supplier and owned loaders are parent-null and use separate dependency directories. The same launcher exercises real `GenericApplicationContext` registration, replacement, identity-safe clear, close cleanup, explicit source override persistence, and failed `SunwayApplication` refresh cleanup.

The custom-number probe configures the supplier through the real `I18nHelper.setMessageSource` setter and passes `AtomicInteger(7)` to `NumberToStringConverter`. The supplier raises `com.sunwayworld.framework.exception.core.ApplicationRuntimeException` with message `Unable format number (7).` and no cause; the owned converter now raises the same class/message. The numeric differential passes 2,828 observations with configured message sources, including AtomicInteger and AtomicLong unsupported `Number` subclasses.

The owned message adapter resolves the registered Spring `ApplicationContext` automatically when no explicit test source is set; `ApplicationContext` itself supplies `MessageSource`. With no context it returns the literal key for `getMessage`, while real configured sources propagate Spring lookup exceptions. No context-null NPE is used as an implementation result.

`NumberToStringDifferentialTest` adds 320 supplier/owned observations across four initial locales and mutated defaults, exact wrapper-class acceptance, subclass rejection, custom and throwing `Number` values, floating precision correction, and non-finite values. It passes alongside the 2,828-observation numeric converter matrix.
